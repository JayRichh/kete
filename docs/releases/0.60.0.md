# 0.60.0

Kete can run a studio of agents: an inbox the orchestrator works through on its own, role cards, a board and a gauntlet view over your repo's own files, a state map, a triage strip, a usage ledger, and an orchestrator that renews itself from a handover note.

- **Accounts for scripts.** `kete profile list --json` prints every account with its 5-hour and weekly readings, live sessions and holds. `kete profile pick` names the account a scripted launch should take and why, and holds it for 10 minutes so the next pick spreads; `--dry-run` shows every candidate and holds nothing, and it exits 3 when no account is free. A reserved account (`kete profile reserve <name>`, Reserve for me in the desktop Accounts view, or `y` in the terminal app's Accounts overlay) stays the default for your own sessions and is never picked for the orchestrator's spawns or a launch with a role card.
- **Studio inbox and autonomy.** `kete studio enable <repo>` points Kete at a folder of inbox notes. When the orchestrator has sat idle for 45 seconds and nobody has typed to it for 2 minutes, Kete hands it a short note naming the new and changed notes, highest priority first, and which accounts have room. Each note is announced once; editing it announces it again. Autonomy A0 to A3 says how far the studio may go: A0 holds idle notes and refuses new sessions in the repo, A1 (the default) plans without pushing, A2 delivers, A3 may tag releases. Only you change it, from your own shell (`kete studio autonomy`) or the Studio page, which asks before raising past A1. `kete studio status` and `kete studio queue` show what the runner would send, or why it is holding.
- **Role cards.** A repo commits `.kete/roles.toml` to name roles, each with a model, effort, tool set, MCP setting, prompt and permission profile. `kete spawn --role runner`, `kete orchestrator spawn --role` and the role picker in the desktop quick prompt and Start orchestrator form apply one, read from the last commit. A role's tool list is the session's whole tool set. A session on a role says its role on its card and pane header. `kete roles check` prints exactly what every role gets.
- **Unattended sessions.** A role marked `unattended` runs without prompts in its own worktree. Allowlist and unattended sessions never force-push or edit governance paths or Kete's own files: Claude's deny rules and `kete _guard`, run on every shell command, each refuse them. An unattended role runs only on an account you accepted yourself with `kete roles accept-bypass <account>`.
- **Studio board.** A studio repo has one page with a column per department, in the desktop app (Studio in the rail) and the terminal app (the `studio_board` action). Each column shows the notes queued to it, its lead and runners with their context against the role's budget, its last gauntlet verdict, what waits on you, and today's tokens and estimated cost. A What needs you strip above the columns lists sessions waiting on you, notes to you, refused launches and a failed orchestrator renewal. On the terminal board, `[` and `]` lower and raise the repo's autonomy. The board reads the repo's files and writes nothing.
- **Gauntlet view.** The Gauntlet lists every verdict in a studio repo by kind, newest first, with its word, who gave it, when and the note. Filter by word or by age. Open a verdict to read its note, tags, reconciled file and evidence, with Open in Kete and Show in Explorer on each file. Open in Studio takes you to the verdict in your local Studio app, and only links to `127.0.0.1` or `localhost` open. A verdict file that names its `reviewer` and `date`, as sound reviews do, shows who signed it and when. In the terminal app, use the `gauntlet_view` verb. Kete never writes a verdict.
- **State map.** Kete keeps a map of each studio repo: its departments, systems, decisions, lanes, pull requests and the agents on them, joined by who owns, depends on, touches or blocks what. The daemon rebuilds it as sessions start and stop and every minute, and writes it to `.kete/state-map.json`, kept out of git. A repo adds its own layer with an extractor named in `.kete/studio.toml`. The Studio page shows the map under the board, `s` on the terminal studio board opens it, and `kete state` prints it. Copy slice (`c`, or `kete state --slice <node>`) gives an agent a short text about one node, under 2 KB.
- **Triage strip.** Type one line under the orchestrator, in the terminal app (`^Q`, then `t`) or the desktop app's strip, or run `kete studio note "<text>" --triage`. Kete files it as a note in the repo's inbox and hands it to the repo's triage desk, which sets where it goes, what it is about and how urgent it is, and answers in one line that the strip shows. A note that repeats an open one is refused and names it. With no `triage` role in the repo the orchestrator takes the note instead.
- **Usage ledger.** Kete records each Claude session's input, output and cache tokens, Claude Code's estimated cost, tool uses and turns for every local day, at the end of each turn. `kete usage` shows today by session, `--by day` or `--by role` regroups it, and `--csv` prints every row. Export usage CSV in either app writes today's rows to your data folder, and the session rail in the desktop app shows today's line for the session. The cost is Claude Code's list-price estimate, not a bill. Turn it off with `usage_ledger` in Settings, Sessions. A desktop or terminal app opened after sessions have run shows today's spend for each at once.
- **Orchestrator renewal.** `kete orchestrator renew --from <note>` hands the orchestrator over to a fresh session once its current turn ends. The new one starts on the same project, harness, model, role card and account, with your handover note as its first prompt, and takes the role. The old one is archived once the new one reports (`--keep-old` keeps it as a worker; `--now` does not wait; `--pick` takes an account the way `kete profile pick` would). If the new session never reports, the old one stays in charge. Renew orchestrator on the orchestrator's session menu does the same from either app.
- **Visual pass.** In the desktop app, the Studio page no longer scrolls sideways once a session runs, the quick prompt's options wrap to a second line instead of squeezing shut in a narrow window, the renew form keeps the focus after a refusal so Escape still closes it, and the palette finds Triage note and Export usage (CSV).
- **Upgrade note.** The protocol moved from 65 to 66 (additive: older apps keep working without the new pages) and the database to migration 37. Run `kete kill` and reopen.
