# 0.56.0: gap analysis and build plan

Target: the session features the Claude Code desktop app shipped in October 2026, built natively
in Kete's desktop and terminal apps where each applies.

## What Kete already has

| Feature | Desktop | Terminal app | Notes |
| --- | --- | --- | --- |
| Repo tree grouped by project, worktrees under each | yes | yes | `overview/repos.ts`, launcher bands |
| Tree updates on session changes | yes | yes | daemon pushes `EntityUpserted`, `SubagentChanged` |
| Tree updates on git changes | 30 s poll, plus a read when a turn ends | 2 s poll (`GIT_POLL`) | the desktop lags commits, checkouts and resets made outside a turn |
| Recent folders on the new-session screen | no | no | the quick prompt picks a repo and worktree from full lists |

| Report back to the parent | subagents only | subagents only | a `kete spawn` child never tells its parent it finished |
| Follow-up as its own session | no | no | `SpawnSiblingAgent` exists for `kete spawn`; neither app sends it |
| Side question in its own session | no | no | |

## Build plan

Each item lands as its own commits with unit tests and, where a flow changes, an end-to-end flow.

1. **Git watcher (desktop).** A cheap stamp per checkout (`HEAD`, `index`, `logs/HEAD`,
   `packed-refs`, `FETCH_HEAD`), read every 2 s while the window has focus. Only a checkout whose
   stamp changed is read again, and a checkout with a running session is re-read every 6 s for
   working-tree edits. A read only replaces entries that changed, so unchanged rows keep their state.
   The terminal app already polls every 2 s.
2. **Subagent model and effort.** The daemon keeps the Agent tool call's `model` and the subagent's
   own effort level. `SubagentSummary` gains `model` and `effort` (protocol 64; 63 is the subagent cleanup in 0.55.0). Both apps show them
   on subagent rows when known.
3. **Follow-up as its own session, and Ask aside.** Both apps send `SpawnSiblingAgent` from the
   follow-up composer ("Start as new session") and from a new Ask aside verb (a side question, the
   `/btw` of the desktop app). The new session nests under the one it came from and opens beside it.
4. **Nested status rollup.** A parent row counts its children: working, needs you, done.
5. **Session rail (desktop) and session line (terminal app).** Where the session runs (local checkout,
   or its cloud session), context use, changed files in its checkout, model and effort.
6. **Move with a report.** Before Move to another checkout, both apps read the source checkout and say
   how many uncommitted files and unpushed commits stay behind, and ask before moving.
7. **Recent folders.** The quick prompt offers the checkouts sessions last started in, one click
   (or one key) each.

## Deferred, and why

- **Saved environments.** A Kete session runs in one checkout. Folder sets need `--add-dir` carried
  through `CreateAgent`, the database and every resume. An SSH host needs a per-session remote daemon,
  where `kete ssh` today moves the whole app. Both are their own release.
- **A session under every repo it touches.** The daemon does not record which paths a session edits.
  It needs the edit tools' `file_path` taken off `PostToolUse`, mapped to checkouts, and pushed as a
  new event (or snapshot field) that both apps fold into their trees.
- **Report back for `kete spawn` children.** Claude subagents report natively. A spawned sibling
  would need the daemon to read the child's last reply and send it to the parent through the same
  path as `kete orchestrator send`, which is privileged today.
- **Continue in the cloud.** Kete has no way to hand a local Claude session to Claude Cloud. The move
  report (item 6) is the first half; the hand-over needs Claude's teleport flow.
- **Suggested follow-ups.** Kete does not read Claude's suggestions out of the transcript, so there is
  nothing to put a Start button on yet. Item 3 starts a typed follow-up.
